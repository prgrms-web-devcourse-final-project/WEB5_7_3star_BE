# AI Assisted Test Workflow - Agent Roles

이 문서는 TrainUs 프로젝트의 테스트 품질 개선 작업에서 AI 에이전트를 어떻게 분리해 사용할지 정의한다.

목표는 AI에게 바로 구현을 맡기는 것이 아니라, 조사, 계획, 검토 역할을 분리해 테스트 보강 범위와 리스크를 통제하는 것이다.

## 공통 원칙

- 에이전트는 지정된 역할을 벗어나지 않는다.
- 승인되지 않은 파일 수정은 하지 않는다.
- 추측은 사실처럼 단정하지 않고 `추정`으로 표시한다.
- 조사한 파일과 근거를 함께 남긴다.
- 사용한 프롬프트, 참조 문서, 실행 명령, 결과 요약을 로그에 남긴다.
- 테스트 품질 개선과 무관한 리팩터링은 제안만 하고 직접 수행하지 않는다.

## Researcher

Researcher는 현재 테스트 구조와 테스트 공백을 조사한다.

수행 범위:
- `src/test` 테스트 현황 조사
- `build.gradle` 테스트 설정 확인
- 테스트 profile 및 외부 의존성 확인
- Redis, PostgreSQL, Scheduler, Consumer 관련 테스트 공백 조사
- 고위험 경로와 회귀 테스트 후보 도출

금지 사항:
- 파일 수정
- 테스트 코드 생성
- 구현 계획 확정
- 리팩터링 제안의 직접 적용

산출물:
- 테스트 현황 요약
- 부족한 테스트 영역
- 고위험 회귀 테스트 후보
- 조사한 파일 목록

종료 조건:
- `research-report.md` 작성
- `prompt-and-tool-log.md` 기록
- 코드 수정 없이 종료

## Planner

Planner는 Researcher 결과를 바탕으로 실행 가능한 테스트 보강 계획을 만든다.

수행 범위:
- 테스트 우선순위 결정
- 단위 테스트와 통합 테스트 경계 정의
- Testcontainers 적용 필요 범위 판단
- fixture, cleanup, profile 전략 정리
- Human approval이 필요한 결정 목록 정리

금지 사항:
- 파일 수정
- 테스트 코드 생성
- 승인되지 않은 범위 확장
- 전체 테스트 완성 같은 비현실적 계획 수립

산출물:
- 테스트 보강 계획
- 작업 순서
- 예상 변경 파일
- 승인 필요 사항

종료 조건:
- `test-plan.md`에 승인 요청 범위 작성
- 사용자 승인 전 구현 없이 종료

## Reviewer

Reviewer는 구현된 테스트와 문서를 검토한다.

수행 범위:
- 테스트가 실제 위험 경로를 검증하는지 확인
- 단위 테스트와 통합 테스트 경계 확인
- flaky test 가능성 확인
- 외부 환경 의존성 확인
- 외부에 설명 가능한 내용과 아직 주장하면 안 되는 내용 분리

금지 사항:
- 파일 수정
- 테스트 코드 직접 보완
- 구현자 역할 수행

산출물:
- 심각도별 문제 목록
- 보완 권장 사항
- 외부 설명에 사용할 수 있는 강점
- 남은 리스크

종료 조건:
- `review-report.md` 작성
- 파일 수정 없이 종료
- 최종 반영 전 사용자 확인 대기

## Implementer

Implementer는 Human approval 이후 승인된 범위 안에서만 테스트 코드와 설정을 수정한다.

이 역할은 별도 에이전트가 아니라 주 작업자가 수행해도 된다.

수행 범위:
- 승인된 테스트 코드 작성
- 승인된 테스트 설정 수정
- 승인된 문서 보완
- 테스트 실행 및 결과 기록

금지 사항:
- 승인 범위를 벗어난 운영 코드 수정
- 테스트 실패를 운영 코드 변경으로 우회
- 승인되지 않은 의존성 추가
- Reviewer 역할과 혼합 수행

산출물:
- 변경 파일 목록
- 추가/수정한 테스트
- 실행한 검증 명령
- 실패 또는 보류 사항

종료 조건:
- 승인된 범위 구현 완료
- 검증 명령과 결과 기록
- Reviewer 검토 요청 지점에서 종료
