# Human Approval Policy

이 문서는 AI 에이전트가 테스트 품질 개선 작업을 수행할 때 사람이 승인해야 하는 경계를 정의한다.

목표는 모든 세부 작업을 사람이 승인하는 것이 아니라, 위험한 결정과 작업 범위를 사람에게 집중시키는 것이다.

## 승인 없이 가능한 작업

- 테스트 파일과 설정 파일의 현황 조사
- 테스트 공백과 위험 경로 분석
- 테스트 후보 제안
- 문서 초안 작성
- 실패 원인 조사
- 승인된 범위 안에서 테스트 코드 초안 작성

## 승인 후 가능한 작업

- 새 테스트 파일 생성
- 기존 테스트 수정
- `build.gradle` 테스트 task 변경
- Testcontainers 의존성 추가
- test profile 설정 변경
- 공통 fixture 또는 테스트 support class 추가
- CI 테스트 실행 단계 추가

## 승인 전 금지 작업

- 운영 코드 수정
- API 응답 형식 변경
- DB schema 변경
- 운영 profile 설정 변경
- Redis key 정책 변경
- 기존 테스트 삭제
- 성능 측정 수치 임의 변경
- 검증되지 않은 수치 또는 외부 설명 자료 추가

## 승인 요청에 포함할 내용

에이전트가 구현 전 승인을 요청할 때는 다음 내용을 포함한다.

- 변경 목적
- 예상 변경 파일
- 테스트 종류
- 외부 의존성 사용 여부
- 실패 시 영향 범위
- 검증 명령
- 이번 작업에서 하지 않을 것

## 승인 지점

- 구현 전 승인: Planner가 `test-plan.md`를 작성한 뒤 필요하다.
- 보완 전 승인: Reviewer가 승인 범위 밖 수정을 요청하면 필요하다.
- 최종 승인: Reviewer 검토와 보완이 끝난 뒤 수동 PR 전에 필요하다.

## 작업 중단 지점

- Researcher는 조사 리포트 작성 후 중단한다.
- Planner는 승인 요청 작성 후 중단한다.
- Reviewer는 리뷰 리포트 작성 후 중단한다.
- Main agent는 승인 없는 구현, PR 생성, push를 진행하지 않는다.

## 승인 기록 형식

```text
승인 일시:
승인 범위:
수정 허용 파일:
수정 금지 파일:
검증 명령:
보류 사항:
```
